# 验证说明

## v1.1.45（2026-11-15）

公开源码使用 ESP32 Arduino 3.3.8、ArduinoJson 7.4.3、LovyanGFX 1.2.21 构建。FQBN 为 `esp32:esp32:esp32s3:PartitionScheme=huge_app,PSRAM=opi,FlashSize=16M,USBMode=hwcdc,CDCOnBoot=default`，参考板为原版 ESP32-S3、16 MB Flash、OPI PSRAM、I2C AHT20/BMP280。屏幕旋转默认 0。

公开镜像使用 `config.h.example` 生成的空凭据配置；未包含用户的 Wi-Fi、API Key、NVS、SPIFFS、Flash 备份或私人会话。构建及附件哈希见 Release 的 `release-build.json` 与 `SHA256SUMS.txt`。

### 当前源码离线回归

`python tools/test-host.py --compiler <C++17编译器或zig路径> --arduinojson <ArduinoJson/src路径>` 完成七组检查：

- 历史：长记录、32KB 加载窗口边界、保留前缀与严格 JSON 校验。
- 排版：常用分式、角标、科学字符与 Markdown 转换。
- 滚动：有界运动、按键状态及尾行跟随逻辑。
- 流式显示：分片处理、逐字显现与思考状态。
- 草稿：双 C 请求确认、A 清空、B 取消、C 继续删字及提示优先级。
- 草稿排版缓存：与完整重建逐项比较，包含历史和布局变更后的失效。
- 音量：繁忙期间 UI 节流与实时 RMS 刷新路径。

七组均通过。这些检查不连接网络、不打开串口、不烧录；不能替代真实 ASR 或硬件验收。

### 开发设备验证与限制

2026-11-14 已在原版开发板完成同批逻辑的应用区刷写和写后校验；先保留完整 Flash 备份，最后 SPIFFS 与升级前逐字节一致。AHT20 检测正常。串口按键与截图检查覆盖草稿二次确认、二值设置 A 切换及多值设置 B/C 调节。用户确认首次录音音量立即变化、文字持续更新、基础操作正常。

草稿排版缓存优化前，本地重复更新 ACK 为 953/875/797 ms；优化后两轮为 47/63/47 ms 与 109/47/47 ms。这只测量 UI 草稿更新，不代表语音识别端到端延迟。用户仍反馈原版识别返回明显延迟，网络握手、上传与服务端最终结果等待尚不能视为消除。

最终双 C + A 确认流程有串口回归与截图证据；未将它表述为用户已对最终流程再次真人验收。公开镜像另行以空配置、更新构建日期及去除私人 SSID 示例的 Web 页面构建，没有再次实刷；开发设备验证不能冒充该公开镜像 SHA 的实机验收。

公式支持是常用 LaTeX/Markdown 子集，并非完整 TeX 排版引擎。当前版本未移植 CAM 多服务商搜索、相机或 TF 功能。私人日志、屏幕内容、录音及完整备份不纳入公开发布。
